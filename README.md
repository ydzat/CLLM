# CLLM — Block-Scan Reader

[English](README.md) · [中文](README.zh-CN.md)

A non-autoregressive language model that reads text as a 2D grid of `T×T` blocks instead of a 1D token stream. Position is sparse (block-granular, permutation-invariant within a block), the FFN is conditional (top-k routed to a fraction of blocks), and generation is discrete diffusion (iterative mask-predict). Motivated by Chinese reading: high information density, block scanning, order tolerance.

> **Status** — spec-driven development. The ~60M-parameter core model, training loop, sampling, and streaming data pipeline are implemented and CPU-smoke-tested. Training runs on RWTH CLAIX (H100); see [development](docs/development.md).

## What it is

The block-scan reader treats text as *graph-like* rather than *string-like*. A fixed-width `W` reshape lays characters into an `H×W` grid partitioned into `T×T` blocks. One block-granular position vector is shared by every token in a block; inside a block, tokens form a permutation-invariant set. A top-k router applies the FFN only to high-semantic-load blocks. Ordered output is reconstructed from unordered block sets via slot attention, generated by iterative mask-predict.

The full design (math, tensors, complexity) lives in [architecture.md](docs/architecture.md); every non-trivial choice has a record in [decisions/](docs/decisions/README.md).

## Key design points

| # | Choice | Home |
|---|--------|------|
| 1 | Char-level tokenization — words are post-hoc, discovered by the model | [0001](docs/decisions/0001-char-level-tokenization.md) |
| 2 | 2D grid + block-granular sparse position; `T` is the order-vs-compute knob | [0002](docs/decisions/0002-sparse-2d-position-and-block-size.md) |
| 3 | Intra-block interaction is content-based (permutation-invariant), never positional | [0003](docs/decisions/0003-content-based-intra-block-interaction.md) |
| 4 | Conditional FFN via top-k routing — FFN runs on only `α` of blocks | [0004](docs/decisions/0004-conditional-ffn-moe-routing.md) |
| 5 | Generation is discrete diffusion — iterative mask-predict, `O(K)` passes | [0005](docs/decisions/0005-discrete-diffusion-generation.md) |
| 6 | Pretraining dataset — Chinese-first (~65%) + EN/code/math | [0006](docs/decisions/0006-dataset-choice.md) |
| 7 | Data pipeline — HPC streaming, zero local download | [0007](docs/decisions/0007-data-pipeline.md) |

## Quick start

**Local — CPU smoke test only (never training):**

```bash
pip install -r requirements.txt
pytest tests/                                  # tiny-model smoke tests
python src/train.py --config configs/dev.yaml  # 3-step sanity run
```

**Training — HPC only.** See [development.md](docs/development.md) for the Git-sync → Apptainer → SLURM workflow. `scripts/train.slurm` submits the smoke run; `scripts/train_real.slurm` trains the full model on streamed SkyPile.
